A template to adapt to the scope of the engagement. The checkboxes are intentionally empty: this document does not describe work already completed. Items that do not apply may be removed or marked “not applicable”.

## 1. Source code and delivered version

- [ ] Specify the repository and the exact version delivered (tag or commit identifier).
- [ ] Confirm who has access to the repository.
- [ ] Describe the prerequisites, dependencies and installation commands.
- [ ] Provide an example configuration without secrets or production data.
- [ ] List the licences and third-party services required for operation.
- [ ] Specify the rights to use and take over the project provided for in the contract.

## 2. Getting started and operations guide

- [ ] Describe the main business workflows and user roles.
- [ ] Document installation and deployment steps.
- [ ] Explain the update procedure and the associated checks.
- [ ] State where to find logs, service status and alerts, if included in the scope.
- [ ] List known limitations and actions that require technical intervention.

## 3. Access inventory

- [ ] List the accounts and services involved: repository, hosting, domain, email and third-party tools, as applicable to the project.
- [ ] Identify the person responsible for each account and its recovery arrangements.
- [ ] Define a secure channel for transferring access; do not put passwords or keys in this document.
- [ ] Verify access for the team taking over the project.
- [ ] Plan to rotate or revoke temporary access at the end of the engagement.

## 4. Backup and restoration — if included in the engagement

- [ ] Specify which data and configurations are backed up.
- [ ] Document the agreed location, frequency and retention period.
- [ ] Identify the person or service responsible for checking backups.
- [ ] Describe a restoration procedure and its prerequisites.
- [ ] Record the date, scope and outcome of the planned restoration test.
- [ ] Describe the rollback procedure after an update, if applicable.

## 5. Acceptance testing and handover

- [ ] Restate the acceptance criteria from the written scope.
- [ ] Record the results of the business workflows that were checked.
- [ ] Document the accessibility and technical SEO checks included in the scope for web interfaces.
- [ ] List outstanding issues, their impact and the agreed way of addressing them.
- [ ] Arrange the planned walkthrough or technical presentation.
- [ ] Distinguish delivered items from enhancements to be quoted separately.
- [ ] Specify the agreed maintenance or follow-up arrangements, where applicable.

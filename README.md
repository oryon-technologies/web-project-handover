# Web project handover checklist · Checklist de livraison web

Un modèle vierge d’[Oryon Technologies](https://oryon-tech.com/) pour préparer la livraison ou la reprise d’un projet web.

A blank template by [Oryon Technologies](https://oryon-tech.com/) for preparing a web project delivery or handover.

## Français

### Le document

La [checklist française](checklists/livraison-fr.md) reprend à l’identique le [modèle public d’Oryon](https://oryon-tech.com/exemples/checklist-livraison-oryon.md). Elle couvre les sources, la documentation, les accès, les sauvegardes lorsqu’elles font partie de la mission, les vérifications et la réception.

Ce document est un **modèle vierge** : ce n’est ni un dossier client, ni le compte rendu d’une prestation réalisée, ni une liste d’obligations universelles. Les livrables et les modalités de réception dépendent du contrat et du périmètre convenus.

### Utilisation

1. Copiez la checklist dans votre espace de travail privé.
2. Renseignez le contexte et adaptez les points au périmètre convenu. Retirez les éléments non applicables ou indiquez « sans objet ».
3. Cochez les points après vérification et consignez les réserves, responsables et prochaines étapes.
4. Transmettez les accès par un canal sécurisé. N’inscrivez pas de mot de passe ou de clé dans la checklist et ne publiez pas votre version remplie avec des données de projet.

Le fichier français reste la source de la [traduction anglaise](checklists/handover-en.md). Les deux versions ont la même portée ; choisissez celle qui convient à votre équipe.

## English

### The document

The [English checklist](checklists/handover-en.md) is a translation of [Oryon’s public French template](https://oryon-tech.com/exemples/checklist-livraison-oryon.md). The [French file](checklists/livraison-fr.md) is reproduced unchanged. The checklist covers source code, documentation, access, backups when included in the engagement, verification and acceptance.

This is a **blank template**, not a client record, a report of completed work or a universal set of requirements. The agreed contract and scope determine the deliverables and acceptance arrangements.

### How to use it

1. Copy the checklist into your private workspace.
2. Fill in the context and adapt the items to the agreed scope. Remove items that do not apply or mark them “not applicable”.
3. Check items after verification and record outstanding issues, owners and next steps.
4. Transfer access through a secure channel. Do not put passwords or keys in the checklist or publish a completed copy containing project data.

The English version follows the French source and has the same scope. Use whichever language suits your team.
